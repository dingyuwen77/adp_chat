# 企业微信网关实施 Roadmap（先 HTTP 本地联调，再真实企微接入；尚未编码）

> **这是实施路线图，不是当前已完成清单。** A～E 是无需公网地址即可独立验收的研发范围；F 是后续真实企业微信接入，不作为 A～E 的前置条件。方案事实 Owner：[docs/wecom-integration/01_网关架构设计.md](01_网关架构设计.md)，日志契约 Owner：[docs/wecom-integration/02_结构化日志事件.md](02_结构化日志事件.md)。可复用能力以本文链接的当前源码为准；每次开工重新读取仓库最新默认分支及适用 Agent_Skills Source Mode，不能用本文件代替源码事实。

## 0. 目标、限制与完成定义

用户可观察结果：企业员工在**企业微信自建应用原生消息会话**发文字，网关通过可信回调确认员工身份，保存消息并快速 ACK，后台交给 ADP 单轮 `chat()`，最后把回答主动推送给该员工。员工切出应用/重新进入不应取消服务端请求；多员工可并行、同员工有序，跨重启能区分哪些动作可恢复、哪些已进入未知结果，不让会议 MCP 被盲目重复执行。

**已经决定**：单企业单应用、正式可信回调的企业微信 UserID 直接给 ADP UserId/VisitorId、稳定派生 ConversationId、员工只有一个逻辑对话、不判断 ADP 是否追问完成、第一版单实例文件状态、JSONL 网关日志、PyCharm + Docker Compose 都能运行、先不使用数据库/Redis、未来可迁移 Cosmos DB **日志**。**当前阶段 A～E 只需要本机/可信内网 HTTP 与测试协议夹具**，不要求公网域名、HTTPS 证书或真实企微应用 Secret。

**尚未实现**：企业微信回调和主动发送、消息调度与清理、网关 JSONL、Cosmos DB、H5 页面。**不提前扩展**：多租户、群聊、附件、OAuth 前端、MCP 写操作身份传递与生产回调之外的内部公共 REST API。当前 `/api/v1/chat` 仍是无鉴权、固定身份的单用户接口，不能被当作企微回调路由，更不能暴露到公网。

工程上的协议/鉴权属于高风险边界；正式实现阶段必须按项目与当前 canonical Agent_Skills 的 Coding/Testing/Docs/Review/Git 门禁进行，不能仅因阶段拆分就降低验证要求。本文是长期 roadmap，不作为第二份自动生成 Change 文档。

## 1. 先处理三个最重要的架构选择

| 设计选择 | 推荐结论 | 实际原因 |
| --- | --- | --- |
| 一条消息一个 JSON vs 追加 JSONL | **JSON 快照做业务状态、JSONL 做日志** | 状态要频繁更新/按 MsgId 定位；追加事件需要回放与压缩。迁移数据库依赖状态接口，不依赖 JSONL |
| 企业微信用户退出应用 | **服务器继续处理 + 企微应用主动推送** | 不是客户端同步 SSE，员工离开时不会取消服务器任务；真正展示/历史依赖企微客户端，要实测 |
| 日志与状态是否共用存储 | **分离** | 诊断日志不能替代可恢复任务状态；Cosmos 故障不能引起 ADP 副作用重复执行 |
| HTTP 与 HTTPS 是否两套程序 | **同一 FastAPI GET/POST 回调路径** | 本地 HTTP 可验证业务协议；以后若满足真实企微可达性要求，可原路径接入 HTTP 或经 TLS 反向代理接入 HTTPS；仅传输层不同 |

## 2. 开发阶段与验收

| 阶段 | 本阶段交付结果 | 是否依赖公网回调 |
| --- | --- | --- |
| A | 身份/会话与 ADP 多用户隔离 | 否 |
| B | HTTP 回调 GET/POST、加解密、去重和最小可靠落盘 | 否 |
| C | 完整文件状态机、调度与重启恢复 | 否 |
| D | 发送抽象、模拟回复及真实发送适配器的隔离测试 | 否 |
| E | JSONL、PyCharm/内网 HTTP、Docker 的 A～E 验收 | 否 |
| F | 企业微信真实回调、主动回复、两名员工端到端验收 | 是，需企业微信可达地址（HTTP/HTTPS） |

每个阶段完成后记录代码变更、模拟/真实依赖边界、验证命令、结果及未覆盖风险。A～E 的外部腾讯 ADP Probe 使用已发布测试应用和受控测试文字；只证明 ADP 当前环境的会话行为，不把固定 ConversationId 当成永久记忆保证。缺少真实企业微信外部入口不阻塞 A～E，但不能把它们称为「企业微信已联通」。

### 阶段 A：源码/协议基线与纯身份函数（第一批）

**依赖**：当前 main、已发布且允许测试的 ADP 应用 AppKey；CorpID、AgentId、两名 UserID 可先使用虚构测试值，不需要真实企微 Secret/回调地址。

实施：
- 保留 [main.py](../../main.py) CLI 和 [src/adp/client.py](../../src/adp/client.py) 的单轮行为。
- 在纯身份函数中使用明确的 CorpID、AgentId、WeCom UserID 和**固定配置的 ADP 逻辑应用名**确定性计算 64 个十六进制字符的 ConversationId；UserId=VisitorId=WeCom UserID，跨进程不存 UserID→ConversationId。真实回调身份只有在阶段 F 完成企业微信验签后才可信，本阶段输入仅为测试身份。
- 核实当前 ADP V2 格式及上下文配置；单元测试和真实跨进程两轮测试分别证明 ID 相同及平台仍能回忆先前信息。

验收：A1 同一模拟员工同一逻辑应用跨重启 ID 一致；A2 不同员工/应用不相同；A3 当前 CLI 与 `/api/v1/chat` 输入输出及 V2 兼容回归不退化；A4 明确提示“固定 ID 不等于永久记忆”；A5 真实 ADP 测试账号跨进程两轮上下文续接有直接证据（环境不可用时如实标为未验证）。

### 阶段 B：企业微信回调接入、协议安全与可靠 ACK

**依赖**：阶段 A，本地 `http://127.0.0.1:8000`、测试 CorpID/AgentId、独立测试 Token 与 EncodingAESKey。**不依赖**真实企微 Secret、公网 HTTP/HTTPS 地址、可信出口 IP 或员工可见范围。

实施：
- 复用或独立扩展现有 FastAPI HTTP 入口及 `GET /wecom/callback`、`POST /wecom/callback`，使用企微规范的签名、回调 URL 校验、加密 XML 解析、ReceiveId/企业/应用校验，且阻止不安全 XML/超大输入。
- 普通文字消息提取受信身份及 MsgId；非文字消息暂明确不支持；与业务无关的事件不送 ADP。
- **在阶段 B 即实现 ACK 前最小可靠存储**：`put_if_absent/get`、稳定 message_key、同目录原子落盘及重复 MsgId 检查；成功持久化后才 ACK，写入失败不伪成功。完整状态机、任务恢复和清理仍由阶段 C 完成；不得让 B 的验收隐式依赖尚未完成的 C。
- 正文和敏感配置不得进入日志。与现有 [src/core/config.py](../../src/core/config.py) 分离企微服务运行配置，不能固定使用本地测试 user_id。

验收：B1 对正式 FastAPI 路由进行本地 HTTP/TestClient 的 GET URL 校验和加密 POST；B2 不合法签名/解密/企业 ID 被拒绝；B3 并发重复 MsgId 只创建一条可靠快照；B4 写盘失败不 ACK；B5 对事件与附件明确分类且不送 ADP；B6 无需公网或真实企微客户端即可复现，但不得宣称平台回调通过。

### 阶段 C：文件状态、任务恢复、并发与 ADP 调用

**依赖**：阶段 B；以 [docs/wecom-integration/01_网关架构设计.md](01_网关架构设计.md) 的状态机为唯一设计 Owner。

实施：
- 在阶段 B 的可靠存储上扩展 `update/list_unfinished/purge`、消息状态版本校验、接收顺序、独占数据目录与崩溃恢复，禁止另写一套重复的 `put_if_absent/get`；目录放 Docker Volume 或独立的本地测试路径。
- 后台从 RECEIVED 领取任务，同一员工的 ConversationId 在同一时刻最多执行一轮，不同员工在配置的 ADP 并发名额内并行。新消息在状态文件中排队，不依赖额外 Redis/数据库。
- **必须先弥补当前 client.py 的 RequestId 边界**：当前 [src/adp/client.py](../../src/adp/client.py) 内部生成 RequestId，外部直到异常/成功才看见。为可靠的 ADP_STARTED 状态，需以最小兼容方式让调用方在实际网络发送前获得并持久化本轮 RequestId（如可校验的预发送 callback/可选 request_id），失败则不发送；不得为了这一点复制整套 SSE。
- ADP 正式完成后先持久化 `REPLY_SAVED`（回复内容可能含敏感信息，要限制访问/保留）；处理/启动异常且结果未知时标 `ADP_UNKNOWN` 并阻塞该员工后续轮次，不盲目重放。
- 进程异常关闭时自动恢复 RECEIVED 和可安全恢复的阶段；未知结果仅记录并待裁定；同一员工保证**接收顺序**，不虚称修复企微网络自身的消息到达重排。
- 以稳定终态时间执行文件清理：建议已接受发送的正文 7 天后清理、去重标记保留至首次接收后 30 天；未决 UNKNOWN/在途绝不直接过期删除，需容量告警和人工处置记录。

验收：C1 不同员工并发且无会话串线；C2 同员工两条按可靠接收顺序执行；C3 模拟刚落盘后崩溃可自动继续；C4 模拟已发起 ADP 后崩溃**不会**自动重复调用；C5 文件损坏/磁盘满/重入/过期清理不破坏去重；C6 原有 CLI 单轮协议不变。

### 阶段 D：回复发送抽象与本地模拟（不要求企微在线）

**依赖**：阶段 C、测试用发送器和企业微信消息发送协议的固定样本；真实企微 Secret、发送权限和可信出口 IP 只在阶段 F 的真实探测中必需。

实施：
- 以同一发送抽象定义“发送目标、回复文本、发送结果/失败分类”，分别提供测试发送器与企业微信应用消息发送适配器；测试端只捕获请求并模拟成功/失败，不实际联网，不复制 ADP 业务处理。真实适配器的 access_token 缓存、`/cgi-bin/message/send`、文本长度及失败转换采用可替换 HTTP 客户端完成协议测试，真实网络调用留给阶段 F。
- ADP 的 `REPLY_SAVED` 必须先持久化。测试送达记 `SEND_SIMULATED` 并记录 `wecom.send.simulated`，不能伪造 `SEND_ACCEPTED` 或 `wecom.send.accepted`。真实发送才允许 `SEND_STARTED → SEND_ACCEPTED/SEND_UNKNOWN`。
- 真实发送的明确可重试失败按错误码有限重试；发送结果未知时不得盲目重发，也不得重新执行 ADP。模拟运行使用独立目录，不接触正式员工数据。
- 同一用户多轮追问仍只是一轮一轮转发，无 `chat_until_complete()` / 文本猜测 / 业务完成判断；不实现 H5 聊天历史查询 API。

验收：D1 两个模拟用户回复目标不串发；D2 真实发送器在 Fake HTTP 上的 payload、Token 缓存、长度及错误分类符合协议；D3 ADP 回复保存后模拟发送成功/失败/未知状态正确且不重复执行 ADP；D4 没有任何模拟事件冒充员工真实已收到，员工离开/返回的真实体验留到阶段 F。

### 阶段 E：JSONL 日志、HTTP 本地/内网与 Docker 联调（当前交付终点）

**依赖**：阶段 A～D 已完成；使用独立测试会话与消息目录、已发布 ADP 测试应用及本机 Python / Docker。**不依赖公网地址、HTTPS 证书或企业微信真实回调配置。**

实施：
- 复用 Python `logging`，为网关增加统一 JSONL Formatter，老 CLI 的文本日志保持兼容；事件字段、脱敏、轮转与未来 Cosmos 边界以 [docs/wecom-integration/02_结构化日志事件.md](02_结构化日志事件.md) 为唯一 Owner。
- 使用 `message_key` 关联入站、ADP 请求、回复保存、模拟发送和错误恢复；默认不记录员工问答正文、Token、AppKey、Secret 或加密密钥。当前不接 Azure SDK，不向 Cosmos DB 写入。
- 在 PyCharm 启动同一 FastAPI 应用，本机用 `127.0.0.1:8000`、固定测试签名 GET/POST 与 TestClient 验证；现有 `/healthz` 和 `/api/v1/chat` 仍按原有单用户 Contract 工作，新 `/wecom/callback` 仅接受企业微信协议格式的可信请求，不增加绕开验签的生产测试接口。
- Docker Compose 和现有离线发布流程在可信内网完成相同 HTTP 测试（目标宿主地址 `10.102.70.82:4560` 只有实际部署可达后才可声称已验证）；使用单进程/单 worker、独占消息目录和持久挂载，核实重启恢复、权限、退出及回滚。不直接将未鉴权的 `/api/v1/chat` 暴露公网。
- 使用受控的真实 ADP 文字两轮 Probe 校验上下文；外部测试需明确环境、费用及潜在 MCP 写操作影响，不能把 Fake SSE 测试等同于真实 ADP 平台记忆。运行原有回归、文档链接与示例检查，不新增 CI Job。
- 完成后同步 [README.md](../../README.md)、[docs/README.md](../README.md) 和必要运维文档，准确区分已实现功能、模拟验收及仍未完成的真实接入。

验收：E1 JSONL 每行可解析、字段可关联、脱敏和清理有效；E2 本机 HTTP 验签/加解密、去重、可靠 ACK、模拟回复完成；E3 PyCharm 与 Docker 使用同一生产逻辑，重启后保留任务状态且不重复未知外部副作用；E4 原有 CLI、单用户 HTTP、配置与会话存储兼容；E5 受控真实 ADP 测试通过（未执行则明确留下独立未验证项）；E6 **明确标记 A～E 本地联调完成，不声称企业微信云端或员工客户端接入成功**。

### 阶段 F：真实企业微信接入与端到端验收（后续独立任务）

**依赖**：阶段 A～E 的验证证据、实际可被企业微信云端访问且符合后台配置要求的回调 URL（HTTP/HTTPS；优先 HTTPS）、真实 CorpID/AgentId、应用 Secret、Token/EncodingAESKey、测试员工可见范围、API 可信公网出口 IP 和可用发送权限。本阶段暂缓，不阻塞阶段 A～E。

实施：
- 先确认目标自建应用是否已有其他系统占用“接收消息 API”回调及原管理员/服务 Owner，禁止直接覆盖或轮换正在使用的 URL、Token、EncodingAESKey；必要时使用独立测试应用或经批准的回调转发。
- 将企业微信实际回调配置到**已经实现的同一个** `GET/POST /wecom/callback`；HTTP 与 HTTPS 不分叉业务实现，若使用 HTTPS 则可由企业可信的 TLS 反向代理终止加密。私有 IP 和 `127.0.0.1` 不可能直接成为企业微信云端可达地址。
- 在正式应用凭证和受控出口 IP 下验证 `access_token` 与 `/cgi-bin/message/send`，真实发送 API 确认接受后才允许记录 `SEND_ACCEPTED`；验证过期/错误码、未知结果与发送失败恢复。
- 用两名真实员工逐项验收：发文字→加密回调→去重落盘→腾讯 ADP 本轮完成→企业微信主动发送；同员工连续多轮、不同员工隔离；退出应用、返回查看、设备差异与网络异常。企业微信 API 接受不等于员工已读或永久保存，须记录实测边界。
- 若未来选择不同渠道（如企业微信智能机器人 WebSocket），须单独批准变更接入协议和身份模型，不能把机器人接入冒充现有自建应用回调升级。

验收：F1 管理后台 URL GET 校验通过，真实加密 POST 回调可达；F2 两名员工真实消息隔离及多轮上下文通过；F3 真实主动发送 API 正常和错误路径通过；F4 离开/返回的体验有实际设备与版本记录；F5 不影响原有回调使用者，并具备可执行回退方案。没有外部可达入口时报告 F `blocked/not started`，不得写成已接入。

## 3. 后续扩展（不属于第一期交付）

| 触发条件 | 扩展方向 | 关键兼容/证据 |
| --- | --- | --- |
| 消息数量、任务查询或多实例确实需要共享写入 | 文件消息存储 → 数据库 | 保留唯一消息键、状态版本、未完成任务、去重标记、原子接管；冻结旧单实例并验证迁移/回滚 |
| 公司确认 Cosmos DB 账户类型、权限、预算与查询需求 | 本地 JSONL → 批量 Cosmos DB 日志采集 | 独立上传进程、稳定事件 id+分区键、上传检查点、重复上传去重、TTL/数据保留、脱敏 |
| 需要自定义 H5 聊天记录页面 | 身份认证的消息历史/状态 REST API | 区分企微原生会话与自定义页面，避免假设企微自动同步 H5 |
| 实际收到图片/文件需求 | 企业微信 MediaId 下载 → ADP 文件输入 | 媒体权限、可用期、大小限制、临时链接安全、失败与清理 |
| ADP Agent 要创建/修改会议 | MCP 可信身份、业务授权、幂等/结果查询 | 不能信任模型填写的操作者，未知 ADP 结果不能重复创建会议 |

## 4. 验证和交付规则

- 当前仓库在本次修改后**仍只有网关文档设计**；文档验证不能证明企业微信消息、SSE、Cosmos 或容器已实现/通过。阶段 A～E 的本地/内网运行证据与阶段 F 的真实接入证据应分别保留，不互相代替。
- 开发期优先用 Mock/Fixture 的协议、文件一致性、并发/崩溃注入测试，真实企微/ADP Probe 另行受控执行，不把假的 SSE 结果冒充真实应用记忆或客户端展示。
