# 可选的文字追问接口

本页面向直接调用 Python Library 的消费者。[main.py](../../main.py)、`adp-chat` 交互 CLI 和 HTTP 接口都经过 [src/application/chat_service.py](../../src/application/chat_service.py)：每条消息只转发一轮，关闭文字追问推断和结构化业务状态解析，不自动索取补答。ADP 在回复里追问时，由用户下一轮发送文字。三种运行方式和会话存储见 [README.md](../../README.md)。

高级接口在 [src/adp/client.py](../../src/adp/client.py)。直接调用 `chat_until_complete()` 时，先调用单轮 `chat()`，将结果交给 `on_result`；只有 `needs_input=True` 才向 `answer_provider` 获取真实答案。补答复用同一会话，每轮请求 ID 独立。回调异常或取消直接传播，不生成答案、不自动重试。

直接 Library 调用使用传入的 `ChatConfig`；它不会自动读取或更新 `session.json`。需要跨调用保持上下文时，调用方应显式传入同一个 `conversation_id`，或在补答时传入上一轮 `reply_to`。这与默认应用服务负责持久化单用户会话的行为不同。

所有文字请求均采用非流式文本输出，`chat()` 仍在 ADP 成功完成后返回完整 `ChatResult`。现有 `on_preview` 回调继续兼容回复消息中的文本追加和替换事件，但不能依赖逐字触发，也不能把收到回调当作本轮成功；最终状态以函数返回或抛出的异常为准。上游仍使用 SSE 传递状态和完整消息，协议边界见 [docs/adp-chat/03_FastAPI服务架构.md](03_FastAPI服务架构.md)。

## 判定边界

正式 `ReplyMethod=15`、未答问卷优先。可选 `detect_text_clarification=true` 对 18 类完整回复使用有限的句式规则，排除正常答案、引用、代码、FAQ、操作说明和可选帮助邀请。首问语境跨补答保留，避免把翻译或创作结果当成追问。有限规则不能保证任意自然语言零误判。

应用已经输出业务 JSON 时，直接 Library 调用可以设置 `structured_interaction=true`，严格依据明确状态，缺失或冲突则报错。见 [docs/adp-chat/02_结构化业务状态.md](02_结构化业务状态.md) 和 [docs/interaction.schema.json](../interaction.schema.json)。这不是腾讯云原生字段；只修改配置不会让三种默认入口启用该解析。

`ClarificationAnswer` 继续支持现有 Widget 作答；动作必须属于上一轮卡片，组件不猜测 ActionType 和 Payload。问卷支持文字、单选和多选；高级文字接口的保留不表示恢复附件输入。

## 验证与兼容

[tests/test_clarification.py](../../tests/test_clarification.py)、[tests/test_text_clarification.py](../../tests/test_text_clarification.py) 和 [tests/test_interaction.py](../../tests/test_interaction.py) 覆盖正式澄清、正常停止、文字规则、业务契约、问卷、Widget、回调取消和文字消费者。默认入口关闭高级判定的回归见 [tests/test_service.py](../../tests/test_service.py)，单次脚本回归见 [tests/test_single_turn.py](../../tests/test_single_turn.py)。

当前仅支持文字输入和明确的 Widget 补答，不提供附件上传。模拟测试不等于云端所有追问模式均已验收；真实 Widget 动作仍需按已发布应用实测。
