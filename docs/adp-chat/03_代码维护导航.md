# 代码维护导航

> 本文描述当前仓库已实现的行为；历史验收数字只代表对应提交与环境，不代替当前生产环境验证。具体字段、配置与执行入口以链接的源码和测试为准。


本文帮助接手维护者从用户可见行为定位到真实实现，不复制接口字段和配置定义。先阅读 [docs/adp-chat/01_FastAPI服务架构.md](01_FastAPI服务架构.md)，部署与故障处理见 [docs/adp-chat/02_Docker部署与运维.md](02_Docker部署与运维.md)。

## 1. 先分清两条入口

**单用户对话**用于本地脚本、CLI 和可信内网同步 HTTP。它们复用一份会话配置和单轮 ADP 调用，不判断追问是否结束。入口为 [main.py](../../main.py)、[src/cli/runner.py](../../src/cli/runner.py)、[src/api/routes.py](../../src/api/routes.py)；编排在 [src/application/chat_service.py](../../src/application/chat_service.py)，同步 ADP 请求在 [src/adp/client.py](../../src/adp/client.py)，会话文件在 [src/storage/session.py](../../src/storage/session.py)。

**企业微信网关**负责可信回调、员工隔离、可靠落盘、后台异步转发和应用消息发送。HTTP 生命周期在 [src/api/app.py](../../src/api/app.py)，回调路由在 [src/api/wecom_routes.py](../../src/api/wecom_routes.py)，验签解密在 [src/wecom/crypto.py](../../src/wecom/crypto.py)，接收判定在 [src/application/wecom_gateway.py](../../src/application/wecom_gateway.py)，后台调度在 [src/application/wecom_worker.py](../../src/application/wecom_worker.py)，异步 ADP 请求在 [src/adp/async_client.py](../../src/adp/async_client.py)，发送适配器在 [src/wecom/sender.py](../../src/wecom/sender.py)，消息快照在 [src/storage/messages.py](../../src/storage/messages.py)。

这两条入口共享 ADP 协议相关实现，但**单用户 HTTP 接口不是企业微信回调入口**，也不能将单用户互斥规则套到不同员工之间。

## 2. 一条企业微信消息怎么走

1. [src/api/wecom_routes.py](../../src/api/wecom_routes.py) 接收 GET 验证或 POST 回调，读取并限制请求大小，再交给网关验证。
2. [src/application/wecom_gateway.py](../../src/application/wecom_gateway.py) 解码消息并由 [src/storage/messages.py](../../src/storage/messages.py) 完成去重、同员工忙碌判定和可靠快照写入。只有接收决策成功落盘后才确认回调。
3. [src/application/wecom_worker.py](../../src/application/wecom_worker.py) 从待处理记录调度异步 ADP 调用；可能已发送但结果未知时，保存 UNKNOWN 而不是盲目重试。
4. [src/wecom/sender.py](../../src/wecom/sender.py) 负责通知发送及结果分类；发送状态与 ADP 会话占用是不同的状态边界。

消息的正式状态、重启恢复和失败分类以 [docs/wecom-integration/01_网关架构设计.md](../wecom-integration/01_网关架构设计.md) 为解释 Owner；统一普通 `.log` 仅用于诊断，不能代替业务快照；已实现的方案 B 与未来 Cosmos DB 采集方案详见 [docs/logging/01_统一日志与Cosmos_DB接入设计.md](../logging/01_统一日志与Cosmos_DB接入设计.md)。

## 4. 开发和验证边界

- 依赖与测试入口以 [pyproject.toml](../../pyproject.toml)、[requirements-dev.txt](../../requirements-dev.txt) 和 [.github/workflows/tests.yml](../../.github/workflows/tests.yml) 为准。普通离线回归可运行 `python -B -X utf8 -m unittest discover -s tests -v`；实际结果取本次环境输出。
- 涉及真实 ADP、企业微信发送、Docker 镜像和跨机器访问时，单元测试不等于外部联调通过；请按运维文档的分层步骤验证。
- 新增或变更配置时先修改配置解析 Owner，再同步示例配置和运维说明；变更协议时核对请求方、响应方和相关测试。
- 不在日志、文档、测试夹具或提交中保存真实 AppKey、应用 Secret、EncodingAESKey、员工原始消息等敏感数据。

## 5. 当前限制

当前项目不是多租户平台。单用户 HTTP 接口没有内置鉴权，必须限定可信内网；网关阶段 F 已开始真实员工联调，但完整真实场景验收尚未关闭。是否可用、当前配置字段、部署命令和阶段进度，分别以代码、配置模板、运维文档与 [docs/wecom-integration/02_实施路线图.md](../wecom-integration/02_实施路线图.md) 为准。
