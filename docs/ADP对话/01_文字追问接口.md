# 可选的文字追问接口

默认 [main.py](../../main.py) 只转发一条文字消息、展示正式回复并退出，不使用本页的自动补答判定。当前默认行为与会话存储见 [README.md](../../README.md)。

保留的 `chat_until_complete()` 和旧 CLI 服务于现有文字消费者：先调用单轮 `chat()`，将结果交给 `on_result`；只有 `needs_input=True` 才向 `answer_provider` 获取真实答案。补答复用同一会话，每轮请求 ID 独立。回调异常或取消直接传播，不生成答案、不自动重试。

## 判定边界

正式 `ReplyMethod=15`、未答问卷优先。可选 `detect_text_clarification=true` 对 18 类完整回复使用有限的句式规则，排除正常答案、引用、代码、FAQ、操作说明和可选帮助邀请。首问语境跨补答保留，避免把翻译或创作结果当成追问。有限规则不能保证任意自然语言零误判。

应用已经输出业务 JSON 时，可以设置 `structured_interaction=true`，严格依据明确状态，缺失或冲突则报错。见 [docs/ADP对话/02_结构化业务状态.md](02_结构化业务状态.md) 和 [docs/interaction.schema.json](../interaction.schema.json)。这不是腾讯云原生字段，默认主入口不会解析它。

`ClarificationAnswer` 继续支持现有 Widget 作答；动作必须属于上一轮卡片，组件不猜测 ActionType 和 Payload。问卷支持文字、单选和多选；高级文字接口的保留不表示恢复附件输入。
